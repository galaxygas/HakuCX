# Guidance for AI agents (and humans in a hurry)

This file is the contract for anyone, human or AI, changing HakuCX. Read it before editing.

## Ground rules

1. **Never fake a feature.** If something cannot work (engine limit, no server, missing API), show it disabled with the reason, or leave it out. No simulated VPNs, fake stats, placeholder data presented as real, or toggles that do nothing.
2. **Never re-enter Servo from a Servo callback.** Delegate methods and `evaluate_javascript` callbacks run while Servo holds internal borrows. Queue work (`State::inbox` / `State::outbox`) and handle it in `State::pump()` after `spin_event_loop()` returns. Violations panic with `RefCell already borrowed`.
3. **Only the UI shell webview may use IPC.** IPC messages from any other webview must be rejected (see `show_console_message`). Never expose the IPC channel, a token, or a privileged API to web content. Extensions have their own channel (`browser/extensions.rs`): calls are checked against the extension's token, the calling context (content scripts get `CONTENT_METHODS` only), and the extension's permissions in `ext_api.rs`, never only in `api.js`.
4. **Resize webviews, not rendering contexts.** Call `WebView::resize`; it resizes the shared context. Resizing the context first makes Servo skip the viewport update.
5. **Pin Servo exactly.** `servo = "=x.y.z"`. Upgrades are their own PR with the API changes from Servo's monthly release notes.
6. **No telemetry, no tracking, no remote code.** Network calls the browser makes on its own (filter lists, feeds, weather) must be user-visible, documented in `docs/NETWORK.md`, and switchable off.
7. **Settings changes go through `haku_core::settings`.** Add fields with defaults; never rename or remove a persisted key without a migration in `Settings::migrate`.
8. **Secrets stay in the core.** Passwords and card numbers go to the UI only when the user asked to see one after Windows Hello (`vault_reveal`) or just typed it (the save prompt). Never fill a password without a user action, never write a vault that failed to open, and never log secrets.
9. **Tests come with logic.** Anything in `haku-core` (or any engine-independent crate) needs unit tests. Run `cargo test -p haku-core` before you commit.

## Style

- Match the surrounding code: comment density, naming and idiom.
- Every source file starts with the MPL-2.0 header.
- Explain *why* in comments, not *what*.
- In the UI, never use `currentColor` or `var(--...)` inside SVG: Servo draws SVG as a separate image. Use `<Icon>` (an icon font) or `useThemeColor()`.
- Zustand selectors must return stable values (`?? NONE`, not `?? []`), or React re-renders forever.
- Keep layout shallow. Servo 0.7 lays out the whole UI after any DOM change, and nested flex/grid containers make that exponentially slower (a settings page took 900 ms per keystroke). Stack content with `display: block` and margins (`> * + * { margin-top }`); use flex only for rows and leaf groups.
- Avoid horizontally overflowing rows (use paging) and small tiled backgrounds (use repeating gradients): both stall or slow Servo's rendering.
- Do not re-render big trees on frequent events: internal pages are memoized; keep selectors narrow.
- Text fields use `Input`/`TextArea` from `components/Field.tsx`, never a controlled `<input value>`: Servo fires `input` events as separate tasks, and a re-render in between eats keystrokes.
- Keep UI strings in sentence case. Do not use Opera trademarks in user-facing text except to say HakuCX is not affiliated.
